## 2. 手动检查的操作流程

1. 初次打开文档显示「未检查」，没有质量问题数量和行内标记，不暗示零问题。
2. 用户点击工具栏「检查文档」，读取当前未保存正文与已生效设置的快照；进入「检查中」，按钮禁用以防重复提交。
3. 执行一次完整检查，完成后打开问题面板，显示数量、问题位置、依据和修改建议；本次检查生成的行内标记与报告对应。
4. 用户修改正文后，报告立即标记「正文已修改，结果已过期，请重新检查」。清除行内标记、停用旧问题的跳转；历史问题可保留供阅读，但不充当当前结果。**不自动重跑**。
5. 点击「重新检查」后产生新报告。自动保存只保存正文，不启动校验。光标/选区变化不使报告过期。
6. 导入、版本恢复、安装远端更新、已生效设置变化同样使结果过期，不启动检查。文档切换时清空上个文档的报告。
7. 检查期间发生正文变化或切换文档，丢弃过期结果，不自动补跑。失败显示「检查失败」和重试入口，不显示通过。
8. 中文输入法正在组合输入时点击检查，提示先完成输入，不自动排队到 compositionend 后执行。
9. 保存冲突时允许手动检查当前本地草稿，并明确标注；文档被删除等不可用状态不接受新检查。

报告状态为 `not-run / running / current / stale / failed`。校验不写正文、不触发保存、不改 revision、不创建版本、不影响撤销历史。

## 3. 规则的具体判定

### 3.1 悬置段

- 条件：同一章/条/附录容器既有直接普通段落，又有直接子条；各段落在子条前后均纳入检查。
- 术语章及其内部容器整章豁免，按 `secType: terms` 识别；旧文档仅在角色缺失时使用标题「术语和定义」兜底，不因任意标题包含「术语」而豁免。
- 其他章节和附录不再为「符号和缩略语」引导语或「重要提示」设置豁免；这是用户指定的项目规则。
- 图、表、注、公式等对象本身不因属于直接 block 就当作普通悬置段；单独的列项引出段如果与子条同挂父容器，仍属于待调整的悬置段，不增加额外豁免。
- 以 warning 提示「此处存在悬置段，请移入相应子条或调整结构」；给定位和建议，不自动移动或删除正文。
- 本期质量规则独立实现该项目口径，并取代质量报告中来自 Resolver 的旧 hanging-paragraph 映射，避免两套规则重报；不借此修改所有导出/操作路径的历史口径。

**依据标签：**「项目约定（2026-10-22）」。GB/T 1.1—2020 7.4 原文为「不宜」且存在其他例外，不能将本项目更严格的规则描述为该标准原文。

### 3.2 列项：只查引出语

- 对每个列项组检查是否存在引出语。当前模型下，候选为同一容器内紧邻列表之前的有效文字段；前一个列表的最后一项、标题、图题/表题、空段不能充当引出语。
- 支持冒号引出的文字，也支持完整句号结束的引出句，不将「必须冒号结尾」写成规则。
- 用结构位置、段内文字与句末形式识别候选，必要时识别「如下、下列、以下、包括」等常见表达；不能要求所有合法表达必须命中某个关键词。
- 该规则验证可识别的引出结构，不以无 LLM 的规则声称已理解任何自然语言。未识别时给「未识别到列项引出语，请核对」，定位到列表并显示前文候选供人工判断。
- 列项类型、样式、层级、各项标点和编号一致性均不在本规则范围。

### 3.3 图表：引出语与提及分别检查

每个有独立 Resolver 编号的图/表检查两项：

| 项目 | 判断范围 | 示例 |
|---|---|---|
| 引出语 | 同一章条内容序列中，图表前最近的有效文字段是否说明并指向该图表 | 「结构见图 1。」「技术要求应符合表 2 的规定。」 |
| 正文提及 | 图表自身内容之外，是否有指向该目标的结构化引用或可明确解析的编号提及 | 「见图1」「按表2执行」 |

- 引出语可以同时满足一次正文提及，不要求再在别处重复提及。
- 图表出现在正文时，在正文中寻找提及；图表出现在附录时，允许所在附录的正文提及，不要求主文跨范围引用每一张附录图表。
- 连续图表共用一个引出段时，该段必须明确指向对应各对象，不能因前面有一段文字就让整组自动通过。允许跨连续图表回看该共享引出段，不跨章条寻找引出语。
- 图题/表题、自动编号、自身表格单元格、图内描述、自身注和脚注、目次与图表清单，不算正文提及。
- 只在后文提及：提及通过，图表前引出语仍提示缺失；在其他章提及：可满足正文提及，但不能替代本地引出语。
- 同一图表缺少两项时，一个条目同时列出缺项，不重复刷出两条相同根因的消息。
- 图表编号和图题生成继续保持原有能力；本期不新增针对图题、版式、编号连续性的用户检查项，相关编号仅作集成回归验证。

### 3.4 附录：主文提及

- 遍历每个附录，以目标 ID 和 Resolver 标签关联主文中的提及。
- 主文指文件 body 部分的实际内容；前言、引言、目次、参考文献、索引和各附录自身不算本规则的主文。
- 「见附录A」「应符合附录 B 的规定」及目标为该附录的结构化引用可计入。
- 附录标题或目录里出现「附录 A」不算；只在附录 A 中提及 B，也不能让 B 通过正文提及检查。
- 未发现时提示「附录 A 未在正文中提及」，定位到附录标题；有提及时可查看来源位置。
- 不判断提及是否足以构成规范性/资料性引用的语义，也不自动改附录性质。

### 3.5 术语：正文至少使用 2 次

- 取术语章实际定义的中文术语名，阈值为 `count >= 2`。0 次或 1 次提示，2 次及以上通过，不要求分布在两个段落。
- 正文计数范围为 body 中术语章、规范性引用文件章之外的实际文字内容，包含段落、列项和表格单元格；排除标题、图表题、前言、引言、附录、参考文献、索引、注、示例、脚注、表脚注、代码和公式源串。
- 不把术语章内的术语名称、英文名、定义或来源计入；不把目录、自动标签计入。
- 同一术语跨粗体/斜体/上标等 inline 样式片段时仍识别；在段/项/单元格边界停止拼接，不把相邻内容凑成术语。
- 结构化 termRef 与其实际显示的术语文本合并为同一个命中，不重复计数；仅有目标 ID 的引用按其目标术语计一次。
- 首版采用规范化后的字面匹配，不做同义词、缩略语、词形和概念推理。多个已定义术语重叠时按最长匹配计入，避免短术语嵌在另一已定义长术语中也重复加分；单字、英文边界及同名术语有单独测试。
- 报告显示「术语 X：正文识别到 1 次，要求至少 2 次」，附可点击的命中上下文；未使用时定位到术语条目。
- 未命中不能据此自动删除术语或认定定义不规范；无法确定主术语名的条目标为未覆盖并说明。

本节正文范围和最长匹配是拟定的实现口径，明确记录以便评审；不将「字面识别」描述为数据库或语义审核。

### 3.6 文本提及的识别与去重

只检查结构化引用会漏掉手工输入的「见表1」，因此建立共享的文本和引用索引：

1. 优先读取结构化引用目标 ID；字面提及使用当前 Resolver 已生成的标签反查，不自行产生编号。
2. 支持正文编号、附录编号、附录内图表号的常见写法，归一化全角/半角字符和编号内部空白；匹配完整编号边界，图1不能匹配图10，表A.1不能匹配表A.10。
3. 支持明确枚举及范围「图1和图2」「表1～表3」；只关联实际存在的目标，不凭范围生成对象。不能明确解析时标为需核对。
4. 不将明显指向其他文件的「GB/T ×× 中的图1」当成本文件图1的有效提及；外部上下文有歧义时不给内部目标通过结论。
5. 保留命中来源 nodeId、原始范围和证据片段；结构化引用显示文本与同一处文本识别去重。
6. 图表题、目录、参考文献、脚注等按各规则的范围排除；同一个索引允许按调用规则过滤，而不是让所有规则共用一个错误的全文计数。

### 3.7 继续保留和排除的能力

保留章条层级与结构检查、受支持内部引用完整性、规范性引用文件有限格式检查。未知出版物不报「编号不存在」；不注日期引用不因缺年份报错。

quality 只按显式规则白名单映射 Resolver 结果：脚注类问题及脚注内部引出的引用问题不进入本期面板；重复 ID 等导致定位不唯一时仅报告文档级解析/定位问题，不新增脚注审核。

**既有兼容边界：** 本次不删除现有脚注编辑、脚注编号、导出完整性保护或旧 MCP `problems` 字段。新 `quality` 与面板不包含脚注/表脚注检查；MCP 原字段仍维持旧契约，不能直接把全部旧 problems 拷入新面板。参考文献也不注册未引用提醒规则。

## 6. 全局约束和交互

- shared 保持无 DOM、浏览器全局、Node I/O、网络依赖的纯 TypeScript；编号逻辑只在 Resolver。
- 首次显示「未检查」；点击运行后才有问题报告。侧栏开关本身不触发重新分析；已过期结果不允许定位。
- 问题按级别与文档位置排序，允许类别筛选。术语问题显示实际次数，图表问题显示两个检查子项及命中证据。
- 同一事实不重复报告；匹配不确定时提示人工核对，不伪称外部事实错误。
- 问题面板与历史侧栏互斥；切换侧栏不更改正文。只有当前报告才显示行内标记，颜色外还有文字/图标区分。
- 底部说明「术语权威性、引用文件有效性和准确性未检查；脚注、表脚注、参考文献提醒不在本期范围」。零问题只表示本期启用规则未发现问题。
- 不引入自动删除、移动、改写或术语替换。修改后需再次手动检查，不自动刷新结论。
- 按用户要求继续现有 Draft PR #57 的 `codex/phase6-validation-plan` 分支，不另建 PR；保护 `.pnpm-store/` 等未跟踪内容。

## 8. 验证与完成条件

以下为实施阶段命令；实际执行结果记录在进度与验收文档中。

| 范围 | 实施阶段命令 |
|---|---|
| shared定向 | `pnpm --filter @ses/shared exec vitest run src/validation --maxWorkers=2` |
| shared全量/构建 | `pnpm --filter @ses/shared test`；`pnpm --filter @ses/shared build` |
| client | `pnpm --filter @ses/client test`；`pnpm --filter @ses/client build` |
| server | `pnpm --filter @ses/server test --runInBand`；`pnpm --filter @ses/server build` |
| 全仓库 | `git diff --check`；`pnpm build` |

人工验收场景：

1. 打开、连续输入、保存和导入都不自动运行；点击检查后才出结果；改正文后变为已过期，重新点击才刷新。
2. 术语章的悬置段不报，其他章节及附录悬置段均报；不自动删改。
3. 列项只有引出语检查，无列项样式和层级告警；完整句引出语不被要求改为冒号。
4. 图表在前文有正确引出语时两项均通过；只有后文提及时仍提示缺引出语；自身题注不计入。
5. 附录在正文未提及则提示；只在目次、前言、引言、自身或另一附录中出现不通过。
6. 术语0/1次提示，2次通过；正文表格使用可计数，词条自身与附录等排除内容不计数；命中上下文可查看。
7. 不出现脚注/表脚注质量问题或未引用文献提醒；既有导出保护保持原行为。
8. 图号完整边界、外部文件引用、术语跨样式/重叠词均符合规则约定，无法识别项明确说明。
9. 检查中输入、切文档、恢复或收到远端变更后旧报告不生效；旧结果不跳错位置。
10. 同快照MCP与前端quality一致，校验不改正文/保存/历史/导出内容。

性能在验收机记录：500/2,000/10,000个带ID混合内容块，分别测文本索引、Resolver、规则、定位与绘制。手动检查目标为2,000块1秒内、10,000块3秒内完成；运行期间按钮可反馈状态且页面可响应。若同步分析阻塞交互，先减少重复解析或改Worker，不用减少规则/隐瞒未覆盖换取达标。以上为目标，非已测性能。
