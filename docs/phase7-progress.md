# Phase 7 优化与完善

## 第一轮改动

- 点击大纲后，对应标题滚到正文视口中央，光标落在可编辑的标题或正文起点。前言、引言按节首定位，接近文档首尾时以可滚动范围为限。Chromium 在宽度为 1,280 和 850 像素的窗口中验证了章、子条和附录标题居中，以及前言跳转。
- 编辑器编号、大纲和交叉引用共用当前文档的 Resolver 结果。仅改变选区时复用编号和标题装饰，正文修改、重排或重新载入后重新计算。回归测试中，移动选区并查看引用目标的整篇文档序列化从 3 次降为 0 次。
- 快捷键帮助补充了 macOS 按键说明，以及下划线、表格后插入段落、纯文本粘贴的快捷键。工具栏提示统一标出 Ctrl/Cmd。

## 长文档第二轮

- 支持 CSS Custom Highlight API 的浏览器直接绘制匹配范围。查找保留全部命中和当前命中，切换命中时复用全文范围。较旧的浏览器沿用编辑器装饰高亮。
- 查找横向表格的命中时，表格自身也会横向滚动。Chromium 已验证最右列的命中会进入视口，查找框保留焦点。
- 节点 ID 检查按需扫描附加图、替代图和表脚注。普通正文输入的回归用例中，此插件的全文遍历从 6 次降为 2 次。

Chromium 无头浏览器加载生产构建，使用 20 章的合成文稿，每段含一处同样的查找词。时间为本机从按键事件到同步处理结束的耗时，以毫秒计。切换耗时取五次中位数。

| 段落及命中数 | 首次查找优化前 → 后 | 切换下一处优化前 → 后 |
| --- | --- | --- |
| 500 | 33 → 9 | 1.5 → 0.5 |
| 2,000 | 131 → 10 | 2.9 → 0.7 |
| 10,000 | 730 → 38 | 16.7 → 2.1 |

10,000 段样例的首次查找到第二个动画帧约由 797 毫秒缩短到 101 毫秒。浏览器也验证了完整计数、跨章查找居中、大纲定位、查找框焦点及自动保存请求中的正文。保存检查使用模拟的本地 API。本轮未观察到开启查找时输入耗时的稳定下降，后续继续测量正文渲染和编号计算。

## 长文本编辑与剪贴板

- Word 等外部内容在浏览器粘贴入口直接使用剪贴板纯文本，跳过富文本解析。合并多行时只检查相邻行首尾，最后统一拼接一次。
- SES 内部粘贴沿用结构和格式。只有片段含内部引用目标时才预演粘贴以检查目标仍然存在。刚打开文件就粘贴，第一次撤销恢复到已打开的内容。
- 普通正文段的纯文本修改复用已有编号。被引用段落及结构变化继续重新计算，引用显示随目标更新。

在同一台机器上用 Chromium 比较修复前后的生产构建。粘贴耗时为剪贴板事件的同步处理时间，输入耗时为五次插入的中位数。

| 合成样例 | 修复前 | 修复后 |
| --- | --- | --- |
| Word 风格剪贴板，5,000 行，约 39 万字符 | 2,030 毫秒 | 505 毫秒 |
| SES 内部复制并粘贴 10,000 段，粘贴阶段 | 1,431 毫秒 | 1,174 毫秒 |
| 10,000 段文稿中修改普通正文 | 110 毫秒 | 39 毫秒 |
| 单段约 16 万字符中修改正文 | 70 毫秒 | 69 毫秒 |

浏览器验证了外部粘贴的完整内容、内部粘贴后的节点 ID 唯一性和一次撤销恢复原稿。单段极长时，主要耗时仍在浏览器排版。

## 范围确认

- 跨页重复表头沿用导出端能力。编辑器已支持合并拆分、行列增删、表注、表脚注和单元格文本格式。
- 大纲拖拽沿用顶层排序。条的层级通过编辑器已有的结构格式命令调整。
- 行内公式已实施，Microsoft Word 的实际渲染验收仍待完成。 [行内公式验收](phase7-inline-formula.md#7-验证)

## 后续优先级

本轮构建中共享前端包和编辑器页面包各约 1 MB，gzip 后分别约 332 kB 和 335 kB。打开性能应同时测量首次加载和本地缓存命中后的表现，区分脚本加载与文档渲染的开销。

| 优先级 | 优化方向 | 验收重点 |
| --- | --- | --- |
| 高 | 大文档编辑性能 | 在 500、2,000、10,000 内容块样例中继续测量冷启动、打开和输入，尤其关注查找开启期间的输入，再判断是否需要减少整篇渲染。 |
| 高 | 撤销重做与编辑引导 | 检查日常输入、表格操作、结构调整和版本恢复的撤销粒度。在帮助中补充质量检查和导出最常用的操作路径。 |
| 高 | Word 公式与真实稿验收 | 在 Word 中核对行内符号字形、角标、行距和「式中」对齐，并检查实际标准稿的跨页表格。 [DOCX 交付验收](wp7.6-delivery-validation.md) |
| 中 | 暗色模式 | 在已有颜色变量的基础上，验证编辑器、工具栏、弹窗和预览的显示，并提供可记忆的模式切换入口。 |
| 单独评估 | 从 DOCX 导入 | 先用代表性标准稿核对章条、列项、表格、公式可转换到哪一层，明确声明无法转换的内容，再确定首版范围。 |
