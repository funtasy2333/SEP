# Phase 7：行内公式（式中符号与正文行内公式）

状态：已实施（一期 2026-10-18 式中符号；二期 2026-10-18 正文、注、表格），属于 `ses-requirements.md` Phase 7「优化与完善」。**Microsoft Word 渲染验收未完成**（见第 7 节）。

## 1. 问题

公式下方「式中：q<sub>V</sub>——体积流量」以及正文中提到的符号，原来只能写成文字加上下标：DOCX 用 Word 字符格式（`w:vertAlign`），PDF 用 HTML `<sub>/<sup>`。主公式则由公式引擎排版（DOCX 为 OMML/Cambria Math，PDF 为 KaTeX）。两者的字体、正斜体、角标大小和位置明显不同，编辑器里也没有上下标输入入口。

## 2. 决策

| 事项 | 决定 |
|---|---|
| 一期（2026-10-16） | 式中符号（`whereList[i].term`）改为行内公式；编辑器式中改为「符号 \| 释义」条目，旧的文字式中可一键转换；输入用 MathLive 可视化编辑器，保留 LaTeX 源码作为备用；MCP 同步支持 |
| 二期（2026-10-18） | 推广到正文类位置：段落（含前言、引言、附录、无题条首段）、列项、注/示例（含表注、图注）、表格单元格、术语定义、式中释义、条文脚注与表脚注 |
| 不放开 | 章/条/附录标题、图题、表题、术语名称与英文名、术语来源、参考文献、元数据。这些内容会进入目次、书签和交叉引用文字 |
| 输入入口 | 工具栏「行内公式」+ `Ctrl/Cmd+Shift+M`；选中带上下标的文字后用同一入口「转为公式」；不做 `$…$` 自动转换 |
| 复杂公式 | 允许，但弹窗提示：含分式、求和、积分、根式、矩阵等时，提示「会撑高所在行，复杂公式建议单独成行」 |
| 编号 | 作为 Phase 7 的一项 |

## 3. 模型与出件

- 行内公式是 `IRInline.formula { id, latex }`（PM 节点 `formulaInline`），出件只消费 LaTeX。
- **导出边界**（`packages/shared/src/renderers/outputBoundary.ts`）按「行内数组所属容器」放行：`paragraph.content`、`where.term`、`where.definition`、`footnote.content`。注、示例、单元格、列项、术语定义里的内容都是段落，因此一并覆盖。以下情况都会被拒绝：
  - 不在上述容器内的公式片段（标题、图表题、术语名、参考文献）；
  - 带 `mathml`/`source` 或 `latex` 为空的；
  - 带 `marks` 或脚注的；
  - 旧 XML 出口中的所有行内公式（GB/T 46687.2 的映射归 WP8）。
- **DOCX**：
  - `@ses/io` 对整篇 IR 通用遍历，收集所有行内公式，用 KaTeX 行内模式（`displayMode:false`）转换为 `<m:oMath>`，按行内公式自己的 id 写入 `formulaOmml`。
  - `renderRun`/`renderInlines` 接收行内公式来源（`InlineFormulaSink`）。公式按 irToPm 顺序输出：文字 → OMML → 脚注 → 表脚注；缺 OMML 时回退为 LaTeX 源码并记 `formula-missing-omml`。
  - 正文类调用点都传入来源；没有来源的调用点（标题等）遇到公式会直接报错，避免公式被静默丢弃。
  - 只含公式的单元格段落不再被当作空段。
- **式中破折号制表位**：Word 不测量 OMML 宽度，由宿主估算后经 `formulaWidths` 传入。规则（单位：汉字宽）：
  - 基线字符汉字计 1、其余计 0.5；
  - 上下标乘 0.7；
  - `mover/munder` 取基线与标记的较大者；
  - 最后加 0.25 余量；
  - 未传入时按 LaTeX 源码保守估算。
- **HTML/PDF**：输出 `<span class="ses-formula-inline" data-latex="…">`；PDF 预渲染时按 KaTeX 行内模式替换。行内 KaTeX 与块级公式同为 KaTeX 默认缩放。PDF 截图中，含简单符号的正文行距均匀；含分式的行会略高。

## 4. 编辑器

- **行内公式**（`InlineFormulaEditing`）：
  - 可插入的文本块为 `stdParagraph`、`paragraph`（单元格内）、`stdListItem`、`note`、`example`、`termDefinition`、`tableFootnote`、`tableFootnoteEntry`、`whereTerm`、`whereDefinition`、`formulaDescription`。
  - 工具栏「行内公式」或 `Ctrl/Cmd+Shift+M`：无选区时插入；选中文字时按旧符号规则预填 LaTeX，确认后替换。若弹窗期间文字被改动，则拒绝替换。
  - 光标在标题等位置时，按钮禁用，快捷键也不响应。
- **式中**：工具栏或斜杠菜单「式中」为光标所在公式追加条目，并打开符号输入。键盘行为：
  - 符号格按 Enter 或 Tab 跳到释义，释义按 Shift-Tab 回到符号；
  - 释义按 Enter 在下方新建一条；
  - 在空条目开头按 Backspace 删除该条。

  公式还有文字式中时，会先弹出转换对照表。
- **显示与编辑**：公式以 KaTeX 行内模式显示；点击、或选中后按 Enter 打开编辑弹窗，写回时核对 nodeId。版本对比中，行内公式显示为 `$latex$`。
- **公式输入弹窗**（`MathInputDialog.vue`）：
  - MathLive 0.110.0 按需加载为独立 chunk（808 kB，gzip 221 kB），主 chunk 大小不变；不加载外部字体与音效。
  - 写回前校验：不能有未填写的占位，KaTeX 必须能解析；MathLive 加载失败时退回 LaTeX 源码输入。
  - 公式较高时显示行高提示。
- **文字符号转公式**（`utils/inlineFormulaLatex.ts`，式中一键转换与选区转换共用）：
  - 只转换纯文字加斜体/上下标标记的符号，字符限于拉丁字母、数字、常用标点、撇号和希腊字母；
  - 基线字母按数学斜体；
  - 脚标沿用作者的标记：带斜体的保持斜体，未标斜体的字母写成 `\mathrm{…}`。

## 5. MCP

写作片段在正文类位置接受 `{"formula": {"latex": "…", "id"?: "…"}}`：段落、注、示例、列项、单元格、术语定义、式中符号与释义。标题、图表题、术语名/来源、参考文献中写公式会给出明确拒绝。写入前用 KaTeX 校验，失败时返回 `invalid-value` 与位置；读出的节点可原样整体替换。写法见 `docs/wp9-authoring-reference.md` 2.2 节与 4.5 节。

## 7. 验证

- **PDF**：行内符号由 KaTeX 排版，与主公式字形一致。
- **DOCX**：正文段落、注、表格单元格中都包含 `<m:oMath>`；式中验收样例的制表位为 862 与 1155 twips。LibreOffice 不渲染本项目输出的 OMML（主公式同样为空），因此**公式外观需在 Microsoft Word 中验收**：
  1. 正文、表格、注、式中的符号，与主公式中同一符号的字体、斜体、角标是否一致；
  2. 式中各条「——」是否对齐，回行是否与释义起点对齐；
  3. 含分式的行内公式所在行的行高是否可以接受；
  4. 双击符号能否作为公式编辑。

## 8. 已知限制

- 标题、图表题、术语名、参考文献中暂不支持行内公式。编辑器的插入入口不会放在这些位置，但复制粘贴仍可能带进去（schema 允许行内节点）；这种情况下导出 DOCX/PDF 时会明确报出位置，不会静默丢失。
- 公式注（`formulaNote`）现有出件整体不支持，因此其中也不能放行内公式。
- 编辑器的查找功能不匹配公式内容。
- server 的 KaTeX 仍锁定 0.16.11（WP5 决定），client/io 为 0.16.44；编辑器预览与 PDF 可能有细小字形差异。
- PDF 的式中条目没有「——」（现有打印样式只排两列），与 DOCX 不一致。这是原有问题，本期未改。
- 结构化式中在旧 XML 出口被拒绝。
