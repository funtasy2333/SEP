# WP7.4 Word 验收记录（2026-09-30）

环境：Microsoft Word for Mac 16.113.2。WPS 未安装，渲染结果未验证。

## 开工前机制样稿

用 `python-docx` 生成一个 75 行跨页表、一个横排节和已有原型的 5 个 OMML 公式；通过 `scripts/docx-check/word_pdf.py` 在 Word 中打开并导出 PDF。核验结果：第 2、3 页重复表头；横排页书眉位于顶部、页码位于底部且连续；分式、比较符与 `&`、求和、积分、根号均可见。此样稿只验证 Word 的机制，不代替产品导出验收。

## 产品导出样稿

生成命令：

```bash
node packages/client/scripts/wp74-sample.mjs "$PWD/tmp-e2e/wp7.4/WP7.4_续表验收样稿.docx"
python3 scripts/docx-check/word_pdf.py \
  "$PWD/tmp-e2e/wp7.4/WP7.4_续表验收样稿.docx" \
  "$PWD/tmp-e2e/wp7.4/WP7.4_续表验收样稿.pdf"
```

样稿经过真实的 `buildDocxBlob` 链；`tmp-e2e/` 被 Git 忽略，供本机人工打开。导出无 warning。DOCX ZIP 与 XML 均可解析，含 14 个 OMML 公式、5 个表段（其中跨页长表分 3 段）、1 张嵌入图片、2 个横排节。Word 未弹出修复提示，成功导出 12 页 PDF。

续表按 Word 样稿量得的行高估算，选择最少的表段页数并尽量均衡分配。调整前四个表段的续页表格下沿约 555 pt；调整后三个表段的续页下沿约 670 pt。为严格保证只有续页显示「（续）」，长表的首段仍从新页开始；导出器无法读取 Word 当时的页内剩余高度，因此表前已有内容时，上一页可能留白。这不是实时自适应分页。用户在 Word 中继续修改行高、字体或页边距后，应重新导出并核对分段。超高合并行组会产生 `table-row-too-tall` warning。封面仍是 WP7.2/7.3 的文件编号占位，属于 WP7.5。WPS 未验证。

自动化回归还覆盖表头跨越表头行数的 rowspan：首段保留原始合并，续段表头截断跨界 rowspan，使续页数据列不偏移。该特殊结构未另做 Word 可视样稿，需在真实复杂表格上继续人工校对。
